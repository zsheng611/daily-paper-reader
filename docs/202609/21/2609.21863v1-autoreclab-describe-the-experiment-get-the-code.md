## 摘要
实证评估是推荐系统（RecSys）研究的核心，但将实验设计转化为可执行代码仍是一项依赖人工且容易出错的任务。我们提出 AutoRecLab，一个基于 Python 的自主推荐系统实验室，能够根据自然语言提示自动完成推荐系统实验。给定一个研究想法，AutoRecLab 会推导出明确的实验需求，构建并验证原型，并迭代地将其扩展为所要求的完整实验。该工作流结合了用于文档查找的检索增强生成（RAG）、静态类型验证以及执行引导的树搜索。在我们的演示中，AutoRecLab 自主实现了一项显式反馈到隐式反馈的转换研究。在涵盖六种算法和三个数据集的基线对比中，9 次运行中有 8 次成功，使用 GPT-5.4-mini 时平均每次运行成本约为 1 美元。

## Abstract
Empirical evaluation is central to recommender-systems (RecSys) research, but turning experimental designs into executable code remains a manual and error-prone task. We present AutoRecLab, a Python-based autonomous RecSys lab that automates RecSys experiments from natural-language prompts. Given a research idea, AutoRecLab derives explicit experiment requirements, builds and validates a prototype, and iteratively expands it into the requested full experiment. The workflow combines retrieval-augmented generation (RAG) for documentation lookup, static type verification, and execution-steered tree search. In our demonstration, AutoRecLab autonomously implements an explicit-to-implicit feedback conversion study. In a baseline comparison across six algorithms and three datasets, 8 of 9 runs succeed at an average cost of approx- imately $1 per run with GPT-5.4-mini.

## 2. 方法论
### 2.1 核心思想
- 将自然语言研究想法转化为**机器可检查的实验需求**，再通过“需求工程—原型—完整实验精炼”三阶段，把研究请求逐步变成可执行、可检查的实验代码与产物。
- 核心目标是让“从研究请求到可执行实验”的翻译过程显式化、可检查，并结合 RecSys 专用软件层与验证步骤。

### 2.2 三阶段流程
- **需求工程**：输入自然语言提示，输出研究计划与两套需求：
  - **原型需求**：小规模、快速运行，通常限定一个数据集、一个基线算法、一个指标截断。
  - **完整需求**：保留完整请求，包括所有指定算法、数据集、指标和可视化。
- **原型阶段**：生成并验证小原型，尽早发现实现错误。
- **精炼阶段**：从可执行原型出发，逐步扩展直到满足完整需求；每次修订都执行并评估，最终返回 Python 代码、生成图表、执行日志和 Markdown 摘要。

### 2.3 关键技术细节
- **代码生成与静态验证**：LLM 生成候选实现，系统进行静态类型检查；发现类型不匹配等错误后进入自动修正循环。
- **RAG 文档服务器（MCP）**：通过 Model Context Protocol 检索 OmniRec、LensKit、RecBole 的索引文档和代码，减少 API 幻觉。
- **执行与树搜索**：
  - 每个候选在独立 workspace 中执行。
  - LLM 评估生成代码和控制台输出，针对每条原型需求判断是否满足、候选是否有 bug。
  - 节点分数定义为满足需求比例：**S ∈ [0,1]**，S 表示需求覆盖率，不代表一般置信度或正确性保证。
  - 候选实现构成搜索树；选择节点时，先决定从 buggy 或 bug-free 集合中采样，再用 **ε-greedy** 选择最高分候选或随机替代，用于改进或调试。
  - 停止条件为某候选达到 **S=1** 或达到配置的迭代上限。
- **执行层**：使用 OmniRec 元框架，支持 230 多个数据集及 RecPack、RecBole、LensKit、Elliot 等库。AutoRecLab 因此受限于 OmniRec 支持的库和数据集。
- **产物保存**：中间状态会 checkpoint，代码、图表、执行日志等保存在专用 workspace。

## 3. 实验设计
- **任务场景**：论文称评估了四个代表性 RecSys 实证场景：
  - 显式反馈到隐式反馈转换实验：MovieLens 1M，比较不同二值化阈值对推荐准确率的影响。
